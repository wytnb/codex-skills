# Windy 景区天气

使用现有本地 Chrome 的 `mcp__chrome_devtools`；复用标签页，不反复导航。读取公开页面，不调用隐藏天气接口或绕过订阅。

目的地推荐先走[完整候选范围与报告校验](references/recommendation.md)：以独立完整候选清单生成全部A/B候选的查询任务。调整优先级不等于删除任务；新增候选用sync补任务。单独天气查询和已选目的地行程仍可直接使用下述控制器。

1. 先确定实际游览区域、当地日期与时段；山区分别覆盖高低游览区。用 [统一控制器](scripts/workflow.cjs) 从 [点位缓存](references/point-atlas.json) 过滤所需点位，保存任务ID、配置指纹及地理证据，避免整库载入上下文。仅新点或角色冲突点补核地名、坐标系与独立海拔；地理编码命中不等于游览角色核验。只复用地理数据，天气每次新查。详见 [定位与证据](references/locations.md)。
2. 按当前客户端时间拆分未来168小时（边界含）与之后时段，保存计划起点；跨日或长暂停后重核边界，不能固定认为某整天都超范围。范围内默认地图 ECMWF，雨、雷暴及云两个图层，每日当地上午/中午/下午；有转雨、云量突变或傍晚活动时补查相邻/18点。之后按景区逐日→中长期趋势→附近区域→同期气候→季节风险取依据，标明代理范围及分歧。
3. 按 [执行说明](references/usage.md) 用控制器后台推进、持久化游标、接回未登记收据、计算缺失图层及补查并生成汇总；按作业量分片。正常只返回进度和汇总，不反复取整页文本/源码/截图。单页串行，相同请求/动作至少隔5秒。独立标签页须先小样本验证；每页自己的队列和断点。超时不等于后台停止，启动结果不明时禁止自动再启动。
4. 坐标、ECMWF、图层菜单、完整时间戳/页面时间、单位、累计时长、加载/重绘检查失败即暂停。工具等待超时先读原页状态；不要重新初始化或刷新。修复后最多一次重试，仍失败记缺口。详见 [执行与恢复](references/usage.md)。

Windy 详情海拔曾残留旧点，重新导航也未可靠消除；不能用于证明海拔已更新。“模型高度”还须注明所属模型来源，不能默认 ECMWF。超过5天的灰图、缺色、空白或受限读数不能解释为零；只用通过核验的选点数值。

输出日期趋势与游览影响、简表、实际点位/海拔来源、查询时间、模型及链接。汇总拒绝非法读取日期和读取时超168小时记录；保留不同读取版本与每点日读取跨度，不能把逐行最新称同一起报。毫米降水与厘米雪量分列，不能直接互换。0毫米不保证无雨，累计3小时不等于下了3小时，云量不是厚度，几个时点不能保证全天；`ok` 仅为页面一致性通过，非预报准确性证明。用benchmark区分全流程与单样本耗时，不捏造token节省率。

正式目的地推荐只通过 `scripts/recommendation.cjs report` 或其 `writeOfficialReport` 导出；它在写入前比对完整清单、逐点逐时段需求、原始收据、降级证据及全部评分行。任一未查/无依据降级/范围不符即拒绝写入。`workflow` 的complete和report.md只表示已提交子任务的进度，不能据此宣称全部候选完成。失败时继续补齐；确实受阻则仅说明进度与缺口，不把未完成改写成正式排名。
